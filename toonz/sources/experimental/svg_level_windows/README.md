# Experimental SVG Level — Windows prototype

This directory contains the first buildable investigation for native, read-only SVG Levels in OpenToonz.

The prototype deliberately does **not** convert SVG artwork to PLI. It keeps the SVG file as the source and rasterizes a complete transparent RGBA frame for display and compositing experiments.

## Current scope

- Windows only.
- Qt 5 Core, Gui, and Svg.
- Loads one SVG document.
- Uses the SVG `viewBox` or intrinsic size to determine its natural frame.
- Rasterizes to a transparent premultiplied `QImage`.
- Supports an optional output width and height.
- Writes a PNG for visual comparison.
- Rejects invalid SVG and unreasonable output dimensions.

This is an isolated probe, not yet part of the OpenToonz application build. It exists to establish the rasterization contract that a future `TSvgImage`/SVG Level adapter will use.

## Build

From a Visual Studio developer command prompt with Qt 5 available:

```bat
cmake -S toonz\sources\experimental\svg_level_windows ^
      -B build\svg-level-probe ^
      -DCMAKE_PREFIX_PATH=C:\Qt\5.15.2\msvc2019_64
cmake --build build\svg-level-probe --config Release
```

## Run

```bat
build\svg-level-probe\Release\svg_level_probe.exe input.svg output.png
```

An explicit output size can be supplied:

```bat
build\svg-level-probe\Release\svg_level_probe.exe input.svg output.png 1920 1080
```

## Intended OpenToonz integration

The next application-facing step will introduce a central SVG open decision:

1. **Open as SVG Level (Experimental)** — retain the SVG source and expose a read-only level whose display frame is generated by this rasterization service.
2. **Convert to Toonz Vector Level** — preserve the existing SVG-to-PLI workflow.

Initially the SVG Level will advertise view/transform/composite capabilities while drawing and palette-editing tools remain unavailable. Column transforms and downstream raster FX will operate on the generated RGBA frame.
